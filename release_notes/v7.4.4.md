→ **排序：fastly.jsdelivr > Netlify（同源）> cdn.jsdelivr**；proxy 大文件吞吐极差，不入选（它的 jsDelivr 转发还被域名白名单 403 拦掉）。

## 二、为什么不能整站搬到 jsDelivr

jsDelivr 的 `gh` 端点**不直出 HTML**：
- `.../index.html` → **301 到 raw.githubusercontent.com**（国内不可达，且返回 text/plain，无法当页面渲染）
- `.../743/`（目录）→ **404**（不做目录索引）

`.wasm` / `.js` / `.json` / `.bin.json` 都正常直出（`content-type: application/wasm` 等）。
所以：**文档留在站点，只有静态资源走镜像**。

## 三、实现

### 1. `web/index.html`（Flutter 构建模板）
`<script src="flutter_bootstrap.js" async>` 改为**运行时选源**：
1. 候选（按实测排序）：`fastly.jsdelivr.net/gh/OGL-Teams/OhGithubLost@web/app/`
   → `./`（同源）→ `cdn.jsdelivr.net/...`
2. 并行探测 13KB 的 `flutter_bootstrap.js`，取**最快**者（上限 1s）
3. 命中后设置 `<base href>` → 之后所有相对资源（bootstrap / main.dart.* /
   canvaskit / skwasm / assets）全部从该源加载
4. 结果写 `localStorage`（`ogl.cdn.v1`，TTL 6 小时）→ 之后**零探测延迟**
5. 全部失败 → 回退 `./`，行为与改动前完全一致

路径从 `location.pathname` 推导，兼容「发布 `app/`」与「发布仓库根」两种部署。

### 2. `tool/web_publish.py`
- **关闭 service worker 注册**：SW 必须同源才能注册，资源走镜像时跨源注册必失败
  （控制台噪音 + 部分版本会等超时）。替代方案是发布根 `_headers` 的一年
  `immutable` 强缓存，二次访问零请求。Flutter 自身也已把 SW 标为 deprecated。
- 每桶发布后同时修正 `<base href>` 与 bootstrap。

## 五、注意
- 版本目录每版新增（`/wasm/744/`、`/js/744/`），桶内 `index.html` 被
  `immutable` 缓存一年 —— 所以**不能原地改历史版本目录**，优化必须走新版本号。
- main 分支零影响。
