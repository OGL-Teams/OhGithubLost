## 修复 · Fixed

### 下载
- **分片不可用时回退单连接**：并发 > 1 且文件 ≤ 1 MiB（分片数不足）时，引擎抛
  `DownloadUnsupported`，调用方此前把它当普通失败 → **所有小文件"下载失败"**。
  现按契约回退到单连接（同一 taskId，页面无感）；服务端忽略 Range 返回 200 时同样回退。
- **分片响应校验 `Content-Range`**：此前只验 206。CDN / 中间设备回**错位区间**时每片长度
  各自正确，却能拼出"长度正确的坏文件"。现逐片比对区间。
- **分片成品读不回来**：分片路径从不 `enqueue`，而后端的 `completedSize` / `fileSha256` /
  `deleteFile` 全靠库任务表解析文件 → 恒为 `null` → 有摘要的资产被判"校验不匹配"，
  且"删坏文件"是空操作。现后端方法接受显式 `path`。
- **暂停 / 重试后进度未归零**：进度条先显示上一轮的假进度；重试后还会挂着上次的失败原因。
- **dispose 后异步回调仍改状态**：通知收敛到 `_safeNotify()`，`dispose` 先立标志再取消令牌；
  入队后若任务已被移除 / 被新入队替换，则**不写回、不入队**。

### DNS（浏览器里比原生更有价值）
- **「DoH 优先」开关此前是死代码**：`preferDoh` 只出现在 `toString` / 摘要里，**没有任何解析
  路径读它**。现新增 `WebDohHttpClient`（走 `package:http` 的 `BrowserClient`），
  按「合法 https 端点 + 有 HTTP 能力」真正选择 DoH 解析器。
- **诚实边界**：浏览器里 DoH **只能查询、不能接管连接**（拿到的 IP 无法回灌给浏览器网络栈）。
  摘要与自检如实写明，不谎称"已接管"。
- **换 DNS 服务商后缓存不作废**：旧答案最长 5 分钟仍被返回。现真实变更时清缓存并留痕。
- **非法 DNS 地址**（空串 / 带协议前缀 / 带端口 / 非 IP）现在入口规格化并给出明确原因。
- **AAAA 记录未补零**（`abc` ≠ `0abc`）；**缓存淘汰语义与注释相反**（把最耐用的先丢）。均已对齐。
- **自检看不出"已回退系统解析"**：现留痕 `via` / `fallback` + 能力上报（`udp/dohQuery/takeover`）。

### Web · 存储
- **IndexedDB 的 object store 从来没被创建**（主因）：`indexedDB.open()` 照样成功，但
  `objectStoreNames = []`，之后每次 `transaction()` 都抛 `NotFoundError`，被 `catch` 吞掉 →
  **所有 blob（草稿 / 缓存 / 大对象）静默落内存，刷新即丢，现场毫无痕迹**。
  现于 `onupgradeneeded` 建仓并如实上报失败。
- **读回值被 JSON 引号包住**：写 `hello` 读回 `"hello"`（缓存 JSON / 文本全部变形）。字符串现原样返回。
- **内存镜像永不失效**：跨标签页删除 / 浏览器清站点数据后仍能从镜像捞出旧值（"设置删了又活过来"）。
  现收紧为「**只有真实写失败才填充镜像**」。
- **写失败降级未 `await`**（竞态丢数据）且失败不可见；现补 `await` 并上报。
- **缓存淘汰计数虚报**（容量上限形同虚设）：`prune()` 无条件移除表头，导致"拒绝淘汰"的热数据
  也被计数并移出列表。现只对真正删掉的计数。
- **分层违规清零**：`base/disk` 不再 import `surface`（改用 `KernelDiagnostics` + 注入回调）。

### Web · 通知权限网关
- **申请失败被谎报为"浏览器不支持"**：浏览器**有** Notification 但申请未成功（无用户手势 /
  iframe 权限策略未放行 / 旧 Safari 回调式 API）→ 网关返回 `unsupported` → 界面给"本应用做不到"
  的**死结论**，而 Web 上没有"跳系统设置"这条路 → 用户被卡住。现回读真实现状，新增可重试的 `error` 态。
- **未授权时谎报"可用"**：`Notification.permission == 'default'` 时判为可用 → 每次 `new Notification()`
  都被浏览器拒掉（"报可用、发全失败"）。现只有 `granted` 才算可用。
- **状态不可恢复**：`default` / 申请失败后**整会话不再重试**（用户刚在站点设置授权也不生效）。现可重测。
- **两条权限判定路径不一致**：设置页 / 自检走同步读，发送器走异步链 → 结论可能互相矛盾。现统一。
- **入口页 iframe 缺 `notifications` 权限**：整个应用跑在 iframe 里，`allow` 未声明该权限会被
  浏览器的权限策略拦下。已补。

### 设置 / 动画
- `kOgLSettingsRowPadding` 声明类型写成 `EdgeInsets` 却赋值 `EdgeInsetsDirectional`
  —— 两者是**兄弟**（都 extends `EdgeInsetsGeometry`），**9 条编译错误、整包构建失败**。已修正。
- **`OgLReveal` 整个类没有 `dispose()`**：错峰用 `Future.delayed`（不可取消），闭包一直捕获
  `this`；它大量出现在列表项构建器里 → 快速滚动 / 翻页可积压**成百上千个**"已卸载但被闭包拖着"
  的 State。现改为可取消 `Timer` + `dispose`。
- **每个路由每帧泄漏 2 个 `CurvedAnimation`**：`buildTransitions` 每帧被调用，里面的
  `CurvedAnimation` 从不 `dispose`，而它给 AnimationController 注册的 `statusListener`
  **只有 dispose 才摘除** → 一次翻页 ≈ 36 个永不摘除的死监听者。改为被动求值的
  `CurveTween(...).animate(...)`，**观感零变化**。
- `types.dart` 的 9 条相对导出多写了一级 `../`（在"以文件路径为入口"的编译里是硬错误）；已对齐。
- 关于页「捐赠」两键指错分片（`shell` → `settings`），此前会把**键名原文**显示给用户；已修。
- **下载失败原因永远显示英文**：`downloadFailed` 是**嵌套对象**，而 i18n 内核只拉平顶层键 →
  4 条原因 × 6 语言 = 24 条已翻译文案**全不可达**。现摊平为 `downloadFailed.*` 平键。
- **老用户的 blob 存储永远好不了**：建仓修复没有升 DB 版本号，跑过坏构建的浏览器本地 DB 已是 v1，
  `onupgradeneeded` 不再触发 → 只有清站点数据才能恢复。现升到 v2，升级回调补建缺失的 store。

## 新增 · Added

### 分级动画预加载
按动效档位（`level` 0–3）分级预加载，策略表集中在**一处**：

| level | 名称 | 策略 |
|---|---|---|
| 0 | 最低级 | **不预加载** |
| 1 | 第二级 | 仅预加载**当前页面** |
| 2 | 倒数第二级 | **预加载最多**，以**全屏动画**为主 |
| 3 | 最高级 | 当前层级 + **下一子层级**的主要动画 |

- 有**数量上限与内存额度**（登记时预扣，超限直接拒收而非排队堆积）——"不要过了"
- **空闲时调度**（每空闲窗口只推进 1–2 项），不与首帧争资源
- **可取消**（切走 tab / 退出路由整组取消并归还额度），模块内不持有 `BuildContext`
- 已接到 4 个页面：首页、搜索、通知中心、仓库页

### 悬浮元素滚动感知
新组件 `ScrollAwareAction`：**向下滚动收边只露 1/4** → **点击立即完全展开** →
**向上滚动自动弹回** → **距底部约半屏强制收起**。滚动判定用累积位移 + 阈值（不是单帧 delta，
避免惯性 / 回弹 / 微抖导致"抽搐"）；收边态仍可点（命中区 ≥ 48dp），拖拽不被拦截。
覆盖 7 处：首页 FAB、仓库页 4 个标签页 FAB、发布页 2 个主操作按钮。

### Web · 多源静态资源加速
- 运行时探测三个源（**fastly.jsdelivr / 本站同源 / cdn.jsdelivr**）取当下最快者，
  结果缓存 6 小时；全部失败回退同源
- 实测（本机网络，brotli 后 1.42MB 的 wasm 主包）：**fastly 1.57s < 同源 3.27s < cdn 3.96s**
- **CanvasKit 改为同源加载**（`--no-web-resources-cdn`）：此前默认从 `www.gstatic.com` 拉
  （国内基本不可达，首屏卡在等待超时——这才是"冷启动慢"的主因，与包大小无关）
- jsDelivr 冷启动需预热（6~19s）：CI 在发布后主动回源拉一遍关键文件，把边缘缓存焐热
- Netlify 缓存策略写在**发布根**（此前写在版本桶里不生效）：入口 / 清单始终校验，
  `/wasm/*`、`/js/*` 一年 `immutable`

## 变更 · Changed

### 设置页重新设计
- 根级：保存失败横幅 → 账户卡 → **5 个可折叠分组**（界面 / 代码与文件 / 存储与网络 /
  关于与帮助 / 日志）→ 危险区
- **行型统一**为 5 种：分组卡片 / 选择行 / 开关行 / 滑杆行 / 危险卡片
- 色板与分段按钮收进**选择弹窗**；每个分组收起时显示**当前值摘要**
- 危险项与普通项在**颜色 + 间距**上拉开
- **功能一项未少**（逐键对照确认；Web 特有的"打开时询问添加到桌面"入口保留）

### 部署
- CI 提交 `app/` 时**不再带 `[skip ci]`** —— Netlify 会连带跳过部署，导致产物永远上不了线；
  防自触发改用 workflow 的 `paths-ignore: app/**`
- Web 双产物：`app/wasm/<版本>/`（dart2wasm 主载）+ `app/js/<版本>/`（dart2js 兜底），
  入口页按 WebAssembly 能力嗅探分流
