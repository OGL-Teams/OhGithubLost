## 严重缺陷 · Critical（数据丢失类）

### 空文件被判定为"远端不存在"，写链路走错分支
- **修复前**：GitHub 对空文件返回 `content == ""`。模型层以 `encoded.isNotEmpty` 判定"有内容"，空文件被归为"无内容"（`text == null`）；读取层再把 `null` 当作"目标不存在"。于是**真实存在的空文件**在保存时被一致性引擎当作"远端没有此文件"处理——要么误报冲突，要么走无基线的裸新建触发 422。用户**无法正常保存空文件**。
- **修复后**：模型层对"非目录且 size == 0"给出**空串哨兵**（内容是合法的空，而非未知）；读取层据此将空文件如实返回为空内容文档，仅在"真拿不到"时才回落"不存在"。空与无，从此是两个概念。

### 编辑器"已保存"闩锁导致保存后的增量编辑静默丢失
- **修复前**：提交成功后 `_saved` 置真且**永不复位**。此后用户继续编辑：返回键的"未保存拦截"直接放行（`canPop` 看 `_saved`），页面销毁时也**不再回写草稿**——增量编辑既无确认弹窗、也无草稿兜底，退出即丢。而标题栏的"未保存"标记仍在显示，与可直接退出的行为自相矛盾。
- **修复后**：引入**已保存版本基准**（`_savedText`）。三处判据（退出拦截、草稿回写、保存态复位）统一改为"与已提交版本比对"：一旦产生新差异，保存态即刻作废、拦截与草稿照常生效。保存后的编辑，与其他任何时刻的编辑同等受保护。

## 功能缺陷 · Fixed（状态与行为）

### AI 流式与错误呈现
- **结束帧携带的正文被丢弃**：Gemini 惯例将最后一段文本与 `finishReason` 放入同一帧；流式循环"见结束即中断"导致**回复结尾被静默截断**。修复后先取出正文、再结束。
- **SSE 末尾无空行时最后一帧丢失**：不少网关/反代在关连接前不发结尾空行，缓冲中的最后一帧（常是尾段正文或结束哨兵）整帧蒸发。修复后流结束时**补一次冲刷**。
- **流式无读超时**：仅设建连超时，半开连接（移动网络常见）会让对话**永久卡在"发送中"**。修复后对帧间隔施加 60 秒空闲超时，挂死连接转为可提示的异常。
- **2xx + 非 JSON 响应体裸逃逸**：网关返回 HTML 错误页（登录页/CDN 拦截）时 `FormatException` 直接穿透到 UI，击穿"界面只认业务异常"的契约。修复后统一折为 `badResponse` 业务异常。
- **HTTP 错误只报状态码**：密钥失效、配额超限、模型名写错在界面上"长得一样"。修复后按三家协议的响应形状抽取服务端 `error.message`（截断防刷屏），用户可见真实原因。

### 设置与持久化
- **一处坏值 = 全部设置丢失**：三处 `num.toInt()` 遇 JSON 中的 `Infinity`/`NaN` 抛 `UnsupportedError`，击穿"反序列化永不抛"纪律——整份设置被默认值覆写且不可逆。修复后全部走**有限性守卫**，坏值回落默认。
- **保存失败的双向静默**：`apply` 成功清错、失败置错均未通知监听者——"保存失败"横幅**该出现时不出现、该消失时不消失**。修复后错误状态变化必发通知。
- **启动初期的设置回退**：`load` 与 `apply` 交错时，迟到的加载用旧快照覆盖内存，用户刚改的设置被静默吞掉、且下次保存把旧值写回磁盘（**永久丢失**）。修复后引入**世代号**：`load` 与 `apply` 双侧递增，迟到者作废。

### GitHub 仓库域
- **改默认分支后全进程用旧值**：默认分支的进程内记忆**无失效点**——切换默认分支后，目录/文件缓存键、建分支、Pages 全部静默落在旧分支，重启前不自愈。修复后更新成功即刷新记忆。
- **裸写路径丢弃 force 语义**：缓存未绑定时的退化写路径既不处理结构化冲突（异常逃逸、无冲突对话框可走），也无视用户已确认的"强制覆盖"（重试永远 409）。修复后 force 改用**当下最新远端基线**，冲突异常折为结构化结果交 UI 呈现。
- **直接写后 30 秒读到旧内容**：绕过一致性引擎的直接写只清了只读缓存、未失效底座内容缓存——"改完再看显示旧值"。修复后写成功即按缓存键精确失效。
- **批量提交可能清空整个仓库**：基线 tree 解析失败时静默以**空 `base_tree`** 建树——提交"成功"，其余文件全部消失。修复后解析不出基线即**中止提交**（宁可不写，不可清仓）。
- **星标状态说谎**：对无权私有仓库，星标查询的 404 与"未星标"不可区分，界面呈现可点的假星标态。修复后语义边界文档化，错误提示不再误导。

### 生命周期与账号
- **登录收尾顺序颠倒**：先删占位账号（激活态被清空并广播"未登录"）再保存正式账号——中途失败时，**原本正常的会话被破坏成未登录**且无回滚。修复后调序：先落定正式账号，成功后再清理占位。
- **僵尸账号与令牌残留**：登录失败清理只删"当前激活"的半成品——验证期间切换过账号时，占位账号连同令牌**永久残留**（安全事故面）。修复后按占位 id 精确清理。
- **AI 助手切号串会话**：会话页未按账号重建，A 的对话上下文在 B 名下继续显示与续写。修复后与首页/搜索一致按账号 key 化。
- **切号残留上一账号的仓库上下文**：会话上下文（仓库/路径）持久化不区分账号。修复后切号即清（内存 + 持久化）。

### 编辑器写路径
- **强制覆盖"确认的是 A、顶掉的是 B"**：冲突对话框展示的是首次失败时的快照；用户确认期间远端若再被推进，第二次写会**静默顶掉一个从未展示过的版本**。修复后 force 前复核远端当前版本，不一致即中止（草稿保留，可重新走冲突流程）。
- **提交成功被误报为失败**：提交后的草稿清理抛错会落入失败分支——用户重存即撞上自己刚提交的版本（伪冲突）。修复后保存态**先**落定，清理失败只记日志。
- **"放弃修改"与在途草稿的竞态**：被放弃的内容可能因写入晚于删除而"复活"为草稿。修复后放弃标志前置到写入入口。
- **"远端已删除"场景的误导预览**：冲突对话框把"远端文件已被删除"渲染成空的内容块。修复后给出专门文案：此时强制覆盖=重新创建。

## 界面交互 · UI

- **新建文件"先关框后校验"**：路径含非法字符时点"创建"→ 对话框关闭、多行内容随控制器销毁**不可恢复丢失**。修复后校验前移进对话框：实时红字提示 + 非法时禁用创建按钮，输入永不因校验失败而丢。
- **AI 历史会话删除无确认**：与全仓"删除必有确认"的惯例不符，且可误删正在查看的会话。修复后补二次确认（6 语言）。
- **发送失败后输入框原文不可找回**：清空在前、失败在后。修复后同步失败路径回填原文。
- **星标/分支加载的已销毁状态访问**：三处异步回调缺挂载防护。修复后补齐。
