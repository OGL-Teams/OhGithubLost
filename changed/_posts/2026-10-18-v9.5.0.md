Correctness sweep: two rounds of cross-domain defect audits, fully fixed and pinned by contract tests.

> **主题**：正确性总攻。两轮系统性功能缺陷检索（AI 协议 / 设置持久化 / 下载状态机 / GitHub 仓库域 / 应用生命周期 / 编辑器写路径 / UI 交互）→ 全量修复 → 契约测试固化。目标只有一个：**数据不丢、状态不假、行为与承诺一致**。

### 严重 · Critical（数据丢失类）

- **空文件被判定为"远端不存在"**：GitHub 对空文件返回空内容，旧逻辑把它与"拿不到内容"混为一谈——真实存在的空文件保存时误报冲突或触发 422，**无法正常保存**。修复后以"空内容 ≠ 无内容"区分：空文件如实返回空内容，仅在真拿不到时才视为不存在。
- **编辑器"已保存"闩锁静默丢稿**：提交成功后再编辑，退出既无确认、也不写草稿——**增量编辑无声消失**，而标题栏还显示"未保存"。修复后三处判据统一以"已提交版本"为基准：一旦有新差异，拦截与草稿即刻恢复生效。

### 修复 · Fixed

- **AI 对话**：回复结尾被截断（结束帧携带的正文被丢弃）；流末尾最后一帧丢失（网关不发结尾空行）；半开连接永久卡"发送中"（无读超时）；网关返回网页错误页时异常裸逃逸；HTTP 错误只报状态码、看不到真实原因。五项全修。
- **设置**：一个坏值（`Infinity`/`NaN`）令**全部设置丢失**且不可逆 → 有限性守卫；"保存失败"横幅该出现不出现、该消失不消失 → 状态变化必通知；启动初期刚改的设置被旧数据覆盖（**永久丢失**）→ 世代号守卫。
- **GitHub 仓库**：切换默认分支后全进程沿用旧值（缓存键错位）；强制覆盖在部分路径下失效（确认后重试永远失败）；写入成功后 30 秒内读到旧内容；批量提交在响应异常时可能**清空整个仓库**（现在宁可不提交、不可清仓）；无权限仓库显示可点的假星标态。
- **账号与生命周期**：登录收尾顺序颠倒，中途失败把正常会话破坏成"未登录"→ 调序；登录失败残留僵尸账号与令牌 → 精确清理；切换账号后 AI 会话串号 → 按账号隔离；切换账号残留上一账号的仓库上下文 → 即清。
- **编辑器**：强制覆盖"确认的是 A、实际顶掉的是 B"（覆盖前复核远端，变了即中止）；提交成功被误报为失败（重存撞上自己的提交）；"放弃修改"的内容可能复活为草稿；"远端已删除"被渲染成空内容块（现在明确告知：此时覆盖=重新创建）。

### 界面 · UI

- 新建文件对话框"先关框后校验"——路径带一个非法字符，**多行内容不可恢复丢失** → 校验移入对话框内实时提示，非法时禁用创建按钮。
- AI 历史会话删除补二次确认（对齐全仓"删除必有确认"惯例）。
- 发送失败回填输入框原文；星标 / Fork / 分支加载三处异步回调补挂载防护。

### 质量 · Quality

- 新增契约回归测试 4 组：非法数字回落、设置加载/应用世代交错、Gemini 结束帧正文保留、OpenAI 结束帧语义。
- 五项静态门禁（分层架构 / UI 令牌 / 性能反模式 / 多语言完整性 / 版本一致性）0 违规；多语言新增 3 组文案 ×6 语言。
