**主题 · Theme** — 5.x 首个正式版：5.0 的交互打磨全部内容 + 一次被探针发现的内核一致性硬化。
*First stable of the 5.x line: everything from 5.0 plus a kernel-consistency hardening found by an adversarial probe.*

> **与 5.0.0-beta 的关系 · Relationship**：本版包含 `v5.0.0-beta` 的全部内容，并补上内核交叉校验。
> **直接升级到 5.1.0 即可**，无需先装 beta。
> *This release includes everything in v5.0.0-beta plus the kernel cross-check. Upgrading straight to 5.1.0 is enough.*

### 新增 · Added

- **内核一致性硬化：清单 ↔ 运行期模块交叉校验 · Manifest coverage cross-check**
  一次性对抗性探针（跑在独立 CI 分支上）发现：**引导清单里声明了某模块、装配时却没有提供它**这种情况，此前既不拒绝也不留痕——应用"看起来正常"，实际少了一整层能力。现在内核在封存总线后逐一比对，缺失项记为 `OGL-BOOT-108`（warn 级诊断 + 引导信任告警）：**仍可启动，但一定留痕**，不误伤可用性。附回归用例。  
  A throwaway adversarial probe on its own CI branch found that a module declared in the boot manifest but never assembled was previously accepted silently. The kernel now cross-checks the manifest against the modules actually provided and records `OGL-BOOT-108` (warn-level diagnostic + boot trust warning): boot still succeeds, but nothing is silent. Covered by a regression test.

- **多连接分片下载 · Multi-connection chunked download**
  用 `Range` 请求把文件切成至多 N 片**并发拉取**，再顺序合并；每片写独立临时文件（规避"共用文件句柄错位写坏"），任一分片失败即清理全部分片——**不交付不完整的文件**；服务端不支持 `Range` 时**自动回退**单连接（同 taskId，页面无感知）。新增设置「下载并发连接数」（1/2/4/8，默认 4）。  
  Files are split into up to N ranges fetched **in parallel** and merged sequentially. Each part uses its own temp file, and any failing part deletes every part — never a half-written file. Servers without `Range` support fall back to a single connection transparently. New setting: download connections (1/2/4/8, default 4).

- **权限自检（每次启动）· Permission self-check on every launch**
  每次启动实测存储（真实写入探针）与通知权限，缺失时以 **warn + 事件码**（`OGL-PERM-001` / `002` / `000`）进通知中心；「关于 → 启动诊断」新增权限自检折叠组。  
  Storage (real write probe) and notification permissions are re-tested on every launch; problems are reported as warnings with event codes, and About → boot diagnostics gains a permission section.

### 变更 · Changed

- **页面过渡重做为单层淡入 + 轻位移 · Page transitions rebuilt**
  去掉整页缩放——`ZoomPageTransitionsBuilder` 要求整页在过渡期间反复重新光栅化，正是"只有页面过渡卡、其它动画不卡"的根因；同时强制 `RepaintBoundary`，过渡期间只重合成、不重绘页面内容。  
  Whole-page scaling is gone (it forced full re-rasterisation each frame — the exact reason transitions stuttered while other animations did not), replaced by a single fade + slight offset inside a `RepaintBoundary`.
- **Actions 长日志分块虚拟化 · Virtualised long logs**
  按行分块（120 行/块）交给 `ListView.builder` 按需渲染，并显示「共 N 行」。  
  Logs are chunked by line (120/chunk) and rendered on demand, with a total line count.
- **通知中心去掉 emoji 风格符号 · Emoji-style glyphs removed**
  `✔ / ▶ / ✗ / ★` 不再出现在用户可见文案里（改由图标与日志级别承载），详情展开带动画。  
  Symbols like ✔ / ▶ / ✗ / ★ are gone from user-visible copy (icons and log levels take over), and detail expansion is animated.
- **安卓返回键统一 · Unified Android back key**
  二级页 / 弹窗 → 抽屉 → 回首页 tab → 首页第一次提示「再按一次退出」、窗口内第二次才退出；**一次误按不会退出应用**。  
  Nested routes/dialogs → drawer → home tab → confirm-then-exit on home; a single stray press never quits the app.

### 修复 · Fixed

- 修掉「页面过渡卡顿」的根因（见上）。
- 修掉通知 / 日志正文里的符号字形（Android 上会被当 emoji 渲染，即用户报告的"emoji 撕裂"）。
- 修掉分片任务下暂停 / 取消 / 重试的语义（走取消令牌，不产生错位文件）。

### 已知限制 · Known limitations

- 分片下载的**暂停 = 重新开始**（不声称续传）；单连接库任务的断点续传不受影响。  
  Pausing a chunked download restarts it rather than resuming; library tasks keep true resume.
- 桌面端仍使用库下载（分片引擎按 `Range` 能力判定，不支持则回退）。  
  Desktop keeps the library downloader; the chunk engine falls back when `Range` is unsupported.
- 翻译由 AI 产出并通过格式 / 占位符校验，但未逐条人工校对。  
  Translations are AI-produced and validated for structure and placeholders, not line-by-line reviewed.
