## 2. 接线四处 / Four wiring points

新增或删除语种时，以下四处必须同步；`i18n_scan.py --check` 会校验其中三处（① ② ③）的一致性，
第四处（④）由设备检测逻辑与测试覆盖。
Adding or removing a locale requires synchronising four sites; `--check` verifies the first three.

| # | 文件 / File | 键名 / Symbol | 作用 / Role | 验证命令 / Verification |
| --- | --- | --- | --- | --- |
| ① | `lib/surface/i18n/og_l_i18n.dart` | `OgLI18n.locales`（`List<OgLLocale>`，30 项） | 设置页语言下拉与运行时语言清单 | `rg -n "static const List<OgLLocale> locales" lib/surface/i18n/og_l_i18n.dart` |
| ② | `lib/surface/settings.dart` | `OgLSettings.languageCodes`（`List<String>`） | 持久化语言代码的合法白名单；`contains` 失败回落 `'zh'`（第 377、1111 行） | `rg -n "languageCodes" lib/surface/settings.dart` |
| ③ | `pubspec.yaml` | `flutter.assets` 中 `- assets/i18n/<code>/`（第 149–178 行） | 编译期打包语言目录；漏声明 → 运行时该语言全是键名；多声明 → 构建失败 | `rg -n "assets/i18n/" pubspec.yaml` |
| ④ | `lib/surface/i18n/og_l_i18n.dart` | `ogLDetectDeviceLocale()` | 首次启动设备语言映射：`languageCode` 不在支持集 → `'zh'`；`zh` + `scriptCode == 'Hant'` → `'zh_Hant'` | `rg -n "ogLDetectDeviceLocale" lib/` |

补充接线点 / Additional consumers：`lib/surface/app/og_l_app.dart` 的 `supportedLocales` 由 `OgLI18n.locales` 映射生成（第 224–226 行）；
`lib/surface/pages/settings_page.dart` 第 655 行与 `lib/surface/pages/legal_text_page.dart` 第 151 行遍历 `OgLI18n.locales` 生成语言选项。
`lib/main.dart` 第 52 行 `kOgLBootManifestJson` 與 i18n 无关，不属接线四处。

接线一致性判据 / Consistency criteria（摘自 `tool/i18n_scan.py`）：

- `OgLI18n.locales` 声明但没有语言包目录 → `[check]` 失败；
- 有目录但 `locales` 未声明 → `[check]` 失败；
- `pubspec.yaml` 声明但目录不存在 → 构建必失败，`[check]` 亦报；
- 目录存在但 `pubspec.yaml` 漏声明 → `[check]` 报「运行时该语言全是键名」。

## 3. 三工具用法与判据 / Three tools: usage and criteria

### 3.1 `tool/i18n_scan.py` — 抽取 + CI 门禁

```bash
python3 tool/i18n_scan.py                                   # 报告模式
python3 tool/i18n_scan.py --check                           # CI 模式，有问题 exit 1
python3 tool/i18n_scan.py --json /tmp/items.json            # 导出中文字符串清单
python3 tool/i18n_scan.py --allowlist tool/i18n_allow.txt   # 每行一条豁免字面量，# 为注释
python3 tool/i18n_scan.py --lib /path/to/lib --i18n /path/to/assets/i18n
```

参数（源码 `argparse` 定义）：`--lib`（默认 `<repo>/lib`）、`--i18n`（默认 `<repo>/assets/i18n`）、
`--json`（输出 JSON 文件路径）、`--check`、`--allowlist`（豁免文本文件）。

判据 / Criteria：

1. `lib/surface/` 下字符串字面量含 CJK 且未被 `LOG_CONTEXT`（`debugPrint(`、`OgLAppLog`、`OgLLogFile`、`assert(`、`throw` 等精确入口）、
   `ALLOW_FILES`（`og_l_i18n.dart` 语言自称）、`ALLOW_ITEMS`（`surface_bridge.dart` 模块描述）、`i18n-allow` 注释或 `--allowlist` 豁免 → 记为「待本地化」；
   非 `lib/surface/` 文件一律按开发者日志处理（`layer_kind()`）。日志上下文判定向前回看 7 行、向后 4 行。
2. 以 `assets/i18n/zh/` 全部 28 个分片为基准，逐语言逐分片比对键集合：缺 key / 多 key 均记为分片差异。
3. 分片值必须是字符串；非字符串（如字典被字符串化）记为值类型错误。
4. `locales` × 目录 × `pubspec.yaml` 三处语言清单必须一致。

退出语义 / Exit：`--check` 且上述任一失败 → **1**；全部通过 → **0**（打印「界面文案 0 处未本地化；分片键集合一致；语言清单三处一致」）。
不带 `--check` 时只报告，始终 0。源码：`tool/i18n_scan.py` 的 `main()`。

### 3.2 `tool/i18n_delta.py` — 增量源值快照

```bash
python3 tool/i18n_delta.py extract --base origin/main --out delta.json --langs ja,ko,es
python3 tool/i18n_delta.py check --langs ja,ko,es
```

位置参数 `extract | check`；选项 `--base`（默认 `origin/main`）、`--out`（默认 `delta.json`）、
`--langs`（默认 24 种非中英语言：`ja,ko,es,pt,it,nl,pl,tr,ar,hi,th,vi,id,ms,uk,cs,sv,da,fi,no,hu,ro,he,el`）。

`extract` 从 git 对象读 `--base` 的 `assets/i18n/zh/` 快照，与工作区逐键比较，输出至 `.translate-work/<out>`：
`{"delta": {shard: [keys]}, "source": {shard: {key: 中文源值}}}`。
`source` 即**源值快照**——译文必须按快照翻译，不得按翻译时刻的工作区值，否则 zh 在中途改动会导致前后批次对同一键给出不同译文。

`check` 读取 `.translate-work/delta.json`（固定文件名），优先从 `source` 取源值、回落当前 zh；
暂存目录 `.translate-work/i18n/<lang>` 存在则优先读它，否则读 `assets/i18n/<lang>`。判据：

- 缺键 → 失败；
- 占位符计数（正则 `\{[^}]+\}|%[sd]|\{\{[^}]+\}\}` 的 `Counter`）不一致 → 失败；
- 源值含 CJK 而译文与源值完全相同 → 「未翻译」失败；
- 跨语言同键译文归一化后不一致 → 仅提示人工复核，**不判失败**。

退出语义：`check` 有失败 → **1**，否则 **0**（打印 `OK: N 语言 x M 键 全部通过`）。源码：`tool/i18n_delta.py`。

### 3.3 `tool/i18n_shard_check.py` — 逐分片译文自检

```bash
python3 tool/i18n_shard_check.py ja                              # 默认目录 .translate-work/i18n/ja
python3 tool/i18n_shard_check.py ja assets/i18n/ja               # 校验主干语言包
```

参数：位置参数 1 = 语言代码；位置参数 2 = 目标目录（缺省 `.translate-work/i18n/<lang>`）。
脚本以 `assets/i18n/zh` 为源，逐分片校验：

1. 目标分片缺失 → `缺失`；
2. `list(src.keys()) != list(dst.keys())` → `键集合/顺序不一致`（顺序也计入）；
3. 值为空或非字符串 → `值非字符串或空`；
4. 占位符（`%\d*\$?[@a-zA-Z]`、`\{\w+\}`、`\$\d+`、`\\n`、`\\t`）计数不一致 → `占位符不一致`；
5. 非 `en` 目标且译文与 `assets/i18n/en/<shard>` 同键值完全相同，且非纯符号、非 `KEEP` 技术词白名单、非纯 ASCII 标识 → `与英文基线同形`。
   `KEEP` 含 `github / release / actions / pr / token / pages / commit / ohgithublost / gist / readme / doh / dns / issue / sha / apk / api / ui / url / oauth / yaml / json / git / id / ok / http / https / md / css / html / debug / info / log / feedissue`。

输出格式 `<lang>: N 分片 / M 键 / problems=K`，最多打印前 25 条问题。退出语义：`problems > 0` → **1**，否则 **0**。
注意脚本内 `ROOT='/root/OhGithubLost'` 为绝对路径常量，换仓库路径时需先修改该常量（待核实：是否计划改为 `__file__` 定根）。

## 4. 标准操作流程 / Standard procedures

### 4.1 新增一条文案 / Adding a key

1. 在 `assets/i18n/zh/<page>.json` 加键（值写中文；GitHub / Release / Actions / PR / Token / Pages / Commit / OhGithubLost 等术语不译）。
2. 页面代码改为 `_t('key')`；若所在表达式为 `const`，去掉 `const`。
3. `python3 tool/sort_imports.py` 整理 import。
4. 生成增量：`python3 tool/i18n_delta.py extract --base origin/main --out delta.json`。
5. 按 `.translate-work/delta.json` 的 `source` 快照翻译 24 种目标语言；逐语言跑
   `python3 tool/i18n_shard_check.py <lang> .translate-work/i18n/<lang>`。
6. 合入暂存译文后 `python3 tool/i18n_delta.py check --langs <逗号分隔语言>`。
7. `python3 tool/i18n_scan.py --check`（必须 exit 0）。

### 4.2 新增一个页面 / Adding a shard

1. 页面文案全部经 `OgLI18n.instance.t(page, key)` 取值。
2. `lib/surface/i18n/og_l_i18n.dart` 的 `OgLI18n.pages` 加页面名——未登记的分片不会被加载。
3. 新建 30 个语种目录下的同名 JSON（键集合与 zh 一致）；新语种目录须同步 §2 四处。
4. `python3 tool/i18n_scan.py --check` + `flutter test test/surface/i18n_test.dart`。

### 4.3 翻译工具的仓库内位置 / In-repo translation tooling

仓库内可用 / Available in-repo：`tool/i18n_translate.py`（选项 `--lang`、`--batch 1-24`、`--list`、
`--dry-run`、`--shards`、`--wire`、`--concurrency`、`--chunk`、`--interval`，默认间隔 2.5 秒）、
`tool/i18n_wire.py`（`--dry-run`、`--file`、`--only`、`--fix-const`）。
原文中提及的 `_setup/ogl_i18n_translate.py` **不在仓库**，不得作为命令依据。
The previously documented `_setup/ogl_i18n_translate.py` is not in this repository and must not be used as a command reference.

## 5. 门禁集成 / CI integration

`.github/workflows/ci.yml` 的 quality job 执行 `python3 tool/i18n_scan.py --check`，失败写入 `/tmp/strict_failures.txt`，
由「严格模式终审」统一 fail。`tool/gate_of_gates.py --fatal` 在临时空 CWD 下调用 `i18n_scan --check`
并要求输出包含「语言清单一致」，同时注入一个 dict 值分片验证 `--check` 必须能拦下。

## 6. 文案豁免纪律 / Waiver discipline

- 属于界面文案：`Text` / 按钮 / 提示 / 校验错误 / 对话框 / 通知中的字符串。
- 不属于界面文案：`OgLAppLog` / `OgLLogFile` / `debugPrint` / `throw` / `assert` 中的开发者日志与诊断；
  非交互层（kernel / base / domain）的全部字符串；`og_l_i18n.dart` 中的语言自称。
- 少数「先拼接、后落盘」的日志载荷无法被扫描器识别时，在字符串上方加 `// i18n-allow: 理由`，
  或使用 `--allowlist` 文件（仅在确非界面文案时使用）。
