## 0. 结论速览

一句话：**颜色令牌本身是合格的（onSurfaceVariant 全档 7.21–10.91:1），但「触达」被 VisualDensity.compact、38dp 标题栏、无语义图片/行、以及暗色 SnackBar 动作文字击穿**——用户感知就是「按钮点不准、读屏念不出、次要文字和边框像没画完」，正是粗糙感的物理来源。

| 维度 | 量化结果 | 判定 |
|---|---|---|
| IconButton 总数 | **65 处 / 22 文件**；其中 `visualDensity: VisualDensity.compact` **11 处** → 48dp 主题下限被覆盖为 **40×40dp** | ❌ 11 处 <48dp |
| 其他小触控 | 标题栏窗口控件 `SizedBox(46×38)`（`desktop_window.dart:215`） | ❌ 双轴不足 |
| tooltip 覆盖 | 65/65 IconButton 均带 tooltip（**零缺失**）；但 `log_search.dart:79,85` tooltip 为 `'↑'`/`'↓'`，等于没有 | ⚠️ 2 处无效 |
| Semantics 覆盖 | 全库 `Semantics(` 仅 **14 处**；search_page 3 个自定义行、3 处 `Image.network` 无语义 | ❌ 读屏断点 |
| 对比度 · 文字 | onSurfaceVariant 7.21–10.91、onSurface 9.52–16.39（明暗全档） | ✅ 全过 4.5:1 |
| 对比度 · 边框 | outlineVariant **1.32–2.00:1**（需 3:1，UI 组件/图形） | ❌ 边界消失感 |
| 对比度 · disabled | onSurface@38% 浅色 **2.28–2.34:1** | ⚠️ 豁免但看不清 |
| 对比度 · 暗色 SnackBar 动作 | `inversePrimary` on `surfaceContainerHighest` = **1.90:1** | 🔴 几乎不可读 |

## 1. 用户可感知问题清单（20 条）

### 🔴 严重（6 条）

**A-S1 · 暗色主题 SnackBar 动作文字 1.90:1，点了什么根本看不见**
- 证据：`lib/surface/theme.dart:264` `backgroundColor: brightness == dark ? scheme.surfaceContainerHighest : scheme.inverseSurface`；`lib/surface/theme.dart:271` `actionTextColor: scheme.inversePrimary`。实测深色 `inversePrimary #435e91` on `surfaceContainerHighest #33353a` = **1.90:1**，远低于 4.5:1（正文）/3:1（大文本）。
- 用户感受：深色模式下每次操作的 SnackBar「撤销/重试」按钮像没印上去，是典型的「粗糙 / 没做完」。
- 修复指令：`theme.dart:271` 改为 `actionTextColor: brightness == Brightness.dark ? scheme.onSurface : scheme.inversePrimary`（深色 onSurface on containerHighest = 9.52:1 ✅）；或按 M3 规范用 `scheme.inversePrimary` 但把深色 `backgroundColor` 改为 `scheme.inverseSurface`（深色 inverseSurface = `#e2e2e9`，inversePrimary 对之为 5.01 ✅）。二选一，禁止现状。

**A-S2 · 11 个图标按钮被压到 40×40，主题 48dp 下限形同虚设**
- 证据：`theme.dart:451–455` 设 `minimumSize: Size(48,48)`，但 `code_editor_toolbar.dart:117,123,129,136,142,148,154`、`log_search.dart:80,86`、`search_page.dart:239`、`release_detail_page.dart:548` 均显式 `visualDensity: VisualDensity.compact` → 48−8 = 40dp。
- 用户感受：编辑器工具栏和日志翻页按钮挨得很近，手指/鼠标一点就点到隔壁，工具感垮掉。
- 修复指令：删除上述 11 处 `visualDensity: VisualDensity.compact` 行（保留主题 `minimumSize: Size(48,48)`）。若工具栏空间不足，改为在 `code_editor_toolbar.dart:110` 的 `SingleChildScrollView` 内横向滚动（已有），不要缩按钮；日志翻页同理。

**A-S3 · 桌面标题栏窗口控件 46×38，两个轴都不够**
- 证据：`desktop_window.dart:43` `kOgLTitleBarHeight = 38`；`desktop_window.dart:211–219` `InkWell` 内 `SizedBox(width: 46, height: 38)`。虽有 `Semantics(button:true,label:)`（`desktop_window.dart:206`）但触控目标仍 <48dp。
- 用户感受：窗口按钮细长一条，桌面触屏/触控板上要瞄准，明显「不像正经桌面工具」。
- 修复指令：把 `kOgLTitleBarHeight` 提升到 **48**（M3/WCAG 2.5.5 目标），`desktop_window.dart:215` 的 `SizedBox` 改 `SizedBox(width: 48, height: 48)`；AppBar `preferredSize`（`:88`）随之变 48，标题栏排版按新高度复核一次。

**A-S4 · 三处自定义可点击行没有 button 语义，读屏完全跳不过去**
- 证据：`search_page.dart:214` Card+InkWell(`onTap` 打开仓库 / `onLongPress` 动作) 无 `Semantics`；`search_page.dart:257` README 展开 InkWell 无 `Semantics`（也无 `expanded` 状态）；`search_page.dart:1060` Issue 行 InkWell 无 `Semantics`。对照正确写法：`discover_rows.dart:70–74`（`button:true,label,excludeSemantics`）、`notifications_page.dart:305–309`（`button:true,toggled,label`）。
- 用户感受：读屏用户滑过搜索结果只听到一串文字，不知道「这行能点」，核心任务流（搜索→进仓库→看 issue）在 B 席视角**断链**。
- 修复指令：三处 `InkWell` 外面各包一层 `Semantics(button: true, label: '<标题>，<副标题>', excludeSemantics: true, child: InkWell(...))`；README 折叠行额外加 `expanded: _readmeExpanded` 与 `onLongPress` 的独立动作入口（已有 IconButton，见 `search_page.dart:238`，需给它读屏标签而非仅 tooltip）。

**A-S5 · 三处 Image.network 无 semanticLabel，图片内容对读屏是空白**
- 证据：`readme_view.dart:563` `Image.network(_url...)` 仅在 `errorBuilder` 里把 alt 渲染为文字（`:568`），正常加载的图无 `semanticLabel`；`file_preview_page.dart:483` `Image.network` 无语义；`repo_page.dart:2370` `Image.network` 无语义。全库 `rg semanticLabel` = 0。
- 用户感受：README 里的架构图、预览图对读屏用户「点了进去什么都没有」，而图片恰恰是内容域最需要描述的部分。
- 修复指令：给三处 `Image.network` 加 `semanticLabel: alt`（README 已有 `alt` 变量可直接复用；文件预览用文件名，仓库图片用 `file.path`）；装饰性图片显式 `semanticLabel: ''` 以免念出 URL。i18n 里为「图片：{alt}」加一条键，复用 `readmeImageAlt`。

**A-S6 · Issue 列表用颜色点表达开关状态，读屏拿不到状态**
- 证据：`search_page.dart:1053–1080`：`final Color stateColor = state == 'closed' ? theme.colorScheme.secondary : theme.colorScheme.primary`，并渲染 4px 圆点（`Container(width: OgLSpace.xxs, height: OgLSpace.xxs, decoration: BoxDecoration(color: stateColor, shape: BoxShape.circle))`），但 meta 文本（`:1096–1104`）只含作者/仓库/时间，**不含 open/closed 文字**。
- 用户感受：色弱用户和读屏用户分不清哪些 issue 还开着——状态信息只靠颜色传达，违反 WCAG 1.3.3（感官特征）。
- 修复指令：在 meta 文本前拼入本地化状态词（`_t('stateOpen')`/`_t('stateClosed')`，i18n 新增两键），并把圆点改成 `Semantics(label: state, child: Container(...))` 或直接 `Icon(Icons.circle, semanticLabel: state, ...)`；与 A-S4 的 `Semantics(button:true,label:...)` 合并为一个节点，避免重复播报。

### 🟡 中（9 条）

**A-M1 · 卡片/分割线/Chip/输入框描边全面低于 3:1，「边界消失感」**
- 证据：`theme.dart:246`（卡片 `side: BorderSide(color: scheme.outlineVariant)`）、`:344`（Divider）、`:355`（Chip side，虽 `BorderSide.none` 但背景与容器差仅 1.32:1）、`:377`（SegmentedButton side）、`:256`（BottomSheet dragHandle）、`settings_page.dart:2358`（色块边框）。实测 outlineVariant 对各级 surface 仅 **1.32–2.00:1**。
- 用户感受：卡片和输入框像浮在页面上没有边，正是用户说的「漂浮感 / 空」。
- 修复指令：上述需承担边界语义的描边统一改 `scheme.outline`（浅色对 surface 4.27:1、深色 5.84:1；对 highest 仍 3.47/3.86 ✅）。纯装饰分隔可保留 outlineVariant，但需在设计系统里登记为「非语义装饰」，不得用于卡片外框。

**A-M2 · 日志翻页 tooltip 是「↑」「↓」，等于没写**
- 证据：`log_search.dart:79` `tooltip: '↑'`、`:85` `tooltip: '↓'`，硬编码符号，未走 i18n。
- 用户感受：悬停只看到一个箭头，和图标本身一样，用户不知道是「上一条/下一条匹配」还是「滚动到顶/底」。
- 修复指令：改为 `tooltip: _t('previousMatch')` / `tooltip: _t('nextMatch')`（`code_editor_field.dart:810,815` 已有同名词条，可直接复用同一 shard 或 shell shard），并使用普通 `VisualDensity.standard`（见 A-S2）。

**A-M3 · disabled 前景在浅色只有 2.28–2.34:1，按钮像被擦掉**
- 证据：`theme.dart` 未给 `FilledButton`/`OutlinedButton`/`TextButton`/`IconButton` 定义 `disabledForegroundColor` / `WidgetState.disabled`，走 Flutter 默认 onSurface@38%。实测浅色 2.28–2.34:1。
- 用户感受：未登录/无权限时按钮文字几乎看不见，用户以为界面没加载出来。
- 修复指令：在 `theme.dart` 的四个按钮 Theme 里显式加 `disabledForegroundColor: scheme.onSurface.withValues(alpha: 0.60)`（浅色对 surface 约 4.6:1，达 4.5:1），`disabledBackgroundColor: scheme.surfaceContainerHigh`；仍要保留 `onPressed: null` 的语义禁用。WCAG 虽豁免 disabled 文本，但可感知性属本轮目标。

**A-M4 · 异步 phase / 错误没有 live region，读屏用户不知道发生了什么**
- 证据：`login_page.dart:430–440`（`_phase` 文本、`_error` 文本 plain `Text`）；`notifier.dart:73–80` 用 `SnackBar` 呈现通知，但全库无 `Semantics(liveRegion: true)` / `announce()`。对照 `05-accessibility.md` §4：状态消息需预挂载 live region，`polite` 优先。
- 用户感受：点登录后屏幕外「正在验证令牌」「令牌无效」对读屏完全静默，用户以为卡死。
- 修复指令：在 `og_l_app.dart:127` 的 `OgLNoticeHost` 内加一个常驻 `Semantics(liveRegion: true, child: Text(_announcement, style: …sizedBox 0/transparent))`，由 notifier 统一写入；登录页 `_phase`/`_error` 变化同步调用该 notifier，而非只 setState。

**A-M5 · 令牌输入框没有 autofillHints，密码管理器用不上**
- 证据：`login_page.dart:375–395` 的 `TextField`（token 输入）只有 `labelText`/`hintText`/`autocorrect: false`，无 `autofillHints`；全库 `rg autofillHints` = 0。
- 用户感受：密码管理器无法自动填入长期令牌，用户只能手抄——违反 WCAG 3.3.8（Accessible Authentication，允许密码管理器）。
- 修复指令：`login_page.dart:376` 附近加 `autofillHints: const <String>[AutofillHints.password]`、`enableSuggestions: false`，并在 `keyboardType: TextInputType.visiblePassword` 明确；`autofillHints` 允许粘贴（不要设 `inputFormatters` 限制粘贴）。

**A-M6 · 2.0x 文字缩放下 Release 资产键列 72dp 不变，挤成竖条**
- 证据：`release_detail_page.dart:428` `SizedBox(width: 72, child: Text(key))`，`Expanded(child: SelectableText(value))`。应用字体缩放夹紧到 2.0（`og_l_app.dart:113`），72dp 不会跟着放大。
- 用户感受：把字号拉到 200% 后键名换行成 3–4 行而值列对着一大片空白，列表变得极难扫读（1.4.4 Reflow 风险）。
- 修复指令：改成 `ConstrainedBox(constraints: const BoxConstraints(minWidth: 72), child: IntrinsicWidth(child: Text(key)))`，或更稳妥地把该 Row 改成 `Wrap` 并在窄屏/大字体时改 Column；加一条 2.0x 的 golden test 锁住。

**A-M7 · 38dp 固定标题栏在 2.0x 下会裁切标题**
